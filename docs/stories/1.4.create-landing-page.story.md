## Dev Notes

### Landing Page Architecture

**Page Structure:**
Landing page is public (no authentication required) and serves as entry point to the application. It includes:
- Hero section with value proposition
- Feature cards highlighting key capabilities
- Navigation to sign-up (primary) and sign-in (secondary)
[Source: architecture/project-structure.md, frontend-architecture.md]

**Navbar Component Strategy:**
The navbar is a server component that:
- Checks authentication status via `auth()` from Clerk
- Renders conditional links based on auth status
- Includes theme toggle for dark mode
- Appears on all pages via root layout
[Source: architecture/frontend-architecture.md#component-organization]

**Responsive Design Requirements:**
- Mobile first approach (375px minimum)
- Breakpoints: 768px (tablet), 1024px (desktop)
- Touch targets minimum 48px for accessibility
- Tailwind responsive classes: `sm:`, `md:`, `lg:`
[Source: architecture/tech-stack.md, security-performance.md#frontend-performance]

### Theme Management

**Dark Mode Implementation:**
- Toggle updates `document.documentElement.classList` (add/remove `dark` class)
- Preference persisted in localStorage under key `theme`
- Tailwind's dark mode plugin detects `dark` class on `<html>`
- All shadcn/ui components support dark mode out of the box
[Source: architecture/tech-stack.md#styling - Tailwind CSS dark mode support]

**shadcn/ui Components:**
Use these components from shadcn/ui:
- `Button` - Reusable button with consistent styling
- `Card` - Container for feature cards
- Icons from shadcn/ui (built on lucide-react)
[Source: architecture/tech-stack.md]

### File Structure

Files created in this story:
- `app/page.tsx` - Landing page with hero and features
- `app/components/navbar.tsx` - Top navigation with auth conditional logic
- `app/components/theme-toggle.tsx` - Dark mode toggle button
- Update: `app/layout.tsx` - Include navbar component
[Source: architecture/project-structure.md]

### Server vs Client Components

**Server Components:**
- `app/layout.tsx` - Root layout (can use `auth()`)
- `app/components/navbar.tsx` - Checks auth status server-side
- `app/page.tsx` - Landing page (can be server)

**Client Components:**
- `app/components/theme-toggle.tsx` - Must be client (localStorage access, onClick handler)
[Source: architecture/frontend-architecture.md#component-organization]

### Dependencies

All required dependencies were installed in Story 1.2:
- `shadcn/ui` - UI components
- `tailwindcss@^3.0` - Dark mode support built-in
- `@clerk/nextjs` - Auth status checking
No additional packages needed.

### Styling Approach

Use Tailwind CSS utility classes:
- Layout: `flex`, `grid`, `gap`, `justify-center`, `items-center`
- Spacing: `px-4`, `py-8`, `mt-12`, etc.
- Responsive: `sm:grid-cols-2 md:grid-cols-3`
- Dark mode: `dark:bg-gray-900`, `dark:text-white`
- Colors: Use consistent palette from Tailwind defaults
[Source: architecture/tech-stack.md]

### Performance Considerations

**Bundle Impact:**
- Landing page should load fast (target < 1.5s FCP)
- Use Next.js Image component if adding images
- Lazy load non-critical components if needed
[Source: architecture/security-performance.md#frontend-performance]

**SEO:**
- Add meta tags in layout for title and description
- Use semantic HTML (h1 for headline, p for text)
- Ensure accessibility with alt text on icons

## Testing

### Testing Standards for This Story
- **Unit Tests:** Can test theme toggle logic in isolation
- **Integration Tests:** Test navbar auth state conditional rendering
- **E2E Tests:** Primary testing approach - verify complete user flows
[Source: architecture/testing-strategy.md]

### Manual Testing Checklist
- [ ] Landing page loads at `http://localhost:3000`
- [ ] Hero section displays headline and subheadline
- [ ] "Get Started" button links to `/sign-up` and navigates correctly
- [ ] Feature cards display all 3 features with icons and descriptions
- [ ] Navbar displays logo/brand name
- [ ] Navbar shows "Sign In" link when logged out
- [ ] Navbar shows "Dashboard" link when logged in
- [ ] Dark mode toggle button is visible and clickable
- [ ] Clicking toggle switches page to dark mode
- [ ] Page refresh maintains dark mode preference (localStorage)
- [ ] Mobile view (375px):
  - [ ] All text is readable
  - [ ] "Get Started" button is tappable (48px+)
  - [ ] Feature cards stack vertically
  - [ ] No horizontal scrolling
- [ ] Tablet view (768px):
  - [ ] Layout adjusts appropriately
  - [ ] Feature cards display in grid
- [ ] Desktop view (1024px+):
  - [ ] Full 3-column feature grid visible
  - [ ] Proper spacing on all sides

### Key Test Scenarios for E2E
1. **Public Access Flow**
   - Navigate to `/` → Page loads without auth → Can view all content
2. **Sign-up Navigation**
   - Click "Get Started" → Navigate to `/sign-up` → Sign-up form displays
3. **Dark Mode Toggle**
   - Click toggle → Dark mode activates → Refresh → Dark mode persists
4. **Auth State Switching**
   - Visit as unauthenticated → See "Sign In" link
   - Sign in → Return to landing → See "Dashboard" link
